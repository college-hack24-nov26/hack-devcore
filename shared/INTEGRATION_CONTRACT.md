# Ripple --- Integration Contract (v0.4)

**Status:** Updated shared integration contract; aligned with agreed
Member 2, Member 3, and Member 4 interfaces.\
**Owner:** Member 2 (Backend & Supabase)\
**Purpose:** Establish a consistent contract for frontend, backend,
graph services, and simulation integration.

## 1. Product vocabulary

-   **Company:** A tenant/workspace that owns supply-chain data.
-   **Supply-chain entity:** A supplier, facility, material, warehouse,
    or customer represented in the network.
-   **Dependency:** A directed relationship between two entities; graph
    processing belongs to Member 3.
-   **Incident / disruption:** An actual event that has happened and is
    recorded.
-   **What-if scenario:** A hypothetical event or set of events; it is
    not an incident and must not be inserted into incident history.
-   **Simulation run:** An execution of a what-if scenario; computation
    belongs to Member 4.
-   **Impact analysis:** The output and interpretation of a simulation.
-   **Recovery plan:** A proposed response to a disruption, generated by
    the simulation engine. Recovery plans are drafts and require human
    approval.

### Recovery Strategy Types

The `RecoveryPlanDraft.strategyType` field identifies the recovery
strategy recommended by the simulation engine.

  Value                     Description
  ------------------------- ----------------------------------------------
  `alternate_supplier`      Use an alternative supplier
  `reroute_transport`       Select an alternative transportation route
  `increase_inventory`      Increase available inventory or safety stock
  `reschedule_production`   Adjust the production schedule
  `reduce_demand`           Reduce or prioritize demand
  `custom`                  Other recovery strategies

For v0.4, `strategyType` uses the `RecoveryStrategyType` TypeScript
union, restricting values to the six agreed strategy types.

``` ts
export type RecoveryStrategyType =
  | "alternate_supplier"
  | "reroute_transport"
  | "increase_inventory"
  | "reschedule_production"
  | "reduce_demand"
  | "custom";
```

## 2. Shared conventions

-   Use `camelCase` for TypeScript properties and JSON fields.
-   IDs are UUID strings. Do not use labels such as `supplier-001` where
    a UUID is required.
-   Timestamps use ISO 8601 date-time strings.
-   Every tenant-owned record and graph object must be scoped by
    `companyId`.
-   Optional fields may be omitted where documented. Nullable fields are
    explicitly represented as `null`.
-   Do not invent missing capacity units, currency values, lead times,
    or other business data.
-   Currency fields use ISO 4217 currency codes, such as `INR` or `USD`.
-   `inventoryShortage` and `estimatedProductionLoss` must state their
    measurement units in the accompanying data/model documentation. The
    unit depends on the affected material or product and must not be
    assumed globally.

## 3. Supply-chain graph contract (Member 3)

The graph service provides a `GraphSnapshot` that the simulation engine
consumes directly. Keep this shape stable across the integration.

``` ts
export type EntityType =
  | "supplier"
  | "facility"
  | "material"
  | "warehouse"
  | "customer";

export type RelationshipType =
  | "supplies"
  | "ships_to"
  | "produces"
  | "stores"
  | "uses"
  | "custom";

export interface GraphNode {
  id: string;
  companyId: string;
  type: EntityType;
  name: string;
  attributes: Record<string, unknown>;
}

export interface GraphEdge {
  id: string;
  companyId: string;
  sourceId: string;
  targetId: string;
  relationshipType: RelationshipType;
  capacity?: number | null;
  capacityUnit?: string;
  materialId?: string | null;
  leadTimeDays?: number | null;
  attributes?: Record<string, unknown>;
}

export interface GraphSnapshot {
  companyId: string;
  nodes: GraphNode[];
  edges: GraphEdge[];
  generatedAt: string;
}
```

### Graph rules

-   `sourceId` and `targetId` refer to node IDs in the same graph
    snapshot.
-   `capacity` is numeric; `capacityUnit` describes its unit (for
    example, `kg/day`, `units/day`, or `tonnes/day`).
-   Do not infer a capacity unit when it is unavailable.
-   `materialId` is optional and nullable.
-   `leadTimeDays` is optional and nullable.
-   Route-specific metadata remains inside `GraphEdge.attributes`; it
    must not be added as new top-level graph fields in v0.4.
-   Known route attribute keys include `routeId`, `distanceKm`,
    `estimatedTravelTimeHours`, `transportCost`, `floodRiskLevel`, and
    `routeStatus`.
-   The graph service owns graph construction and graph traversal. The
    simulation engine consumes the snapshot and must not silently
    redefine its structure.

## 4. Scenario input contract (Member 4)

A what-if scenario describes a hypothetical disruption. It is not an
actual incident and must not be written to incident history merely
because it is simulated.

``` ts
export interface ScenarioEvent {
  id: string;
  type: string;
  durationHours: number;
  targetKind: string;
  targetId: string;
  targetType?: EntityType;
  severity: Severity;
  capacityReductionPercent?: number;
  description?: string;
}

export interface ScenarioInput {
  companyId: string;
  name: string;
  description?: string;
  startAt: string;
  events: ScenarioEvent[];
}
```

### Scenario rules

-   Use `type`, not `eventType`.
-   Use `durationHours`, not `durationDays`.
-   `targetKind` describes the kind of target being disrupted;
    `targetId` identifies that target.
-   `targetType` may be supplied when the target maps to a graph
    `EntityType`.
-   `startAt` is an ISO 8601 date-time string.
-   `capacityReductionPercent`, when supplied, represents a percentage
    reduction. Do not treat it as an absolute capacity value.
-   Scenario input is hypothetical and should remain separate from
    actual incident records.

## 5. Simulation result contract (Member 4)

The simulation engine returns a `SimulationResult`. This is the
canonical top-level result shape for v0.4.

``` ts
export type SimulationStatus = "completed" | "failed";
export type SimulationMode = "hypothetical";
export type Severity = "low" | "medium" | "high" | "critical";

export interface SimulationResult {
  simulationId: string;
  scenarioId: string;
  status: SimulationStatus;
  simulationMode: SimulationMode;
  impact: ImpactResult;
  recoveryPlans: RecoveryPlanDraft[];
  assumptions: string[];
  warnings: string[];
}
```

### Result rules

-   `simulationId` identifies this simulation run.
-   `scenarioId` identifies the scenario that was simulated.
-   `status` is `completed` or `failed`.
-   `simulationMode` is `hypothetical` for this version.
-   `impact` contains the calculated impact summary.
-   `recoveryPlans` contains proposed recovery-plan drafts, not
    automatically approved actions.
-   `assumptions` records assumptions made by the engine.
-   `warnings` records limitations, missing data, or conditions that
    affect interpretation.

## 6. Impact result contract

``` ts
export interface FinancialImpact {
  bestCase: number | null;
  expectedCase: number | null;
  worstCase: number | null;
  currency: string;
}

export interface ImpactResult {
  affectedEntityIds: string[];
  affectedEntities: number;
  affectedSuppliers: number;
  affectedFacilities: number;
  affectedWarehouses: number;
  impactedOrders: number | null;
  inventoryShortage: number | null;
  estimatedProductionLoss: number | null;
  estimatedDelayDays: number | null;
  financialImpact: FinancialImpact;
  severity: Severity;
}
```

### Impact rules

-   `affectedEntityIds` contains UUIDs for affected graph entities.
-   The `affectedEntities`, `affectedSuppliers`, `affectedFacilities`,
    The `affectedEntities`, `affectedSuppliers`, `affectedFacilities`, and
    `affectedWarehouses` fields are counts. `impactedOrders` is a count when
    order data is available, and null when order data is unavailable.
    A value of 0 means order data was available and no orders were impacted.
-   `inventoryShortage` is a quantity, not a count of entities. Its unit
    must be made explicit for the relevant material/product; do not
    assume one universal unit.
-   `estimatedProductionLoss` is a quantity. Its unit must be made
    explicit for the relevant product/material; do not assume one
    universal unit.
-   `estimatedDelayDays` is measured in days.
-   `financialImpact` provides best-case, expected-case, and worst-case
    estimates. Amounts use the currency identified by `currency`.
-   Currency values use ISO 4217 codes.
-   Unknown or unavailable estimates must be `null`, not fabricated zero
    values.
-   `severity` uses the shared `Severity` type.

## 7. Recovery plan and action draft contracts

Recovery plans are recommendations generated by the simulation engine.
They are not executed automatically and require human approval.

``` ts
export type RecoveryStrategyType =
  | "alternate_supplier"
  | "reroute_transport"
  | "increase_inventory"
  | "reschedule_production"
  | "reduce_demand"
  | "custom";

export type RecoveryFeasibility =
  | "feasible"
  | "conditional"
  | "infeasible";

export interface RecoveryActionDraft {
  id: string;
  actionType: string;
  description: string;
  targetEntityId?: string;
  estimatedCost?: number | null;
  currencyCode?: string | null;
  estimatedLeadTimeDays?: number | null;
  rationale: string;
}

export interface RecoveryPlanDraft {
  id: string;
  name: string;
  description: string;
  strategyType: RecoveryStrategyType;
  estimatedCost: number | null;
  currencyCode: string;
  recoveryTimeHours: number | null;
  expectedImpactReductionPercent: number | null;
  feasibility: RecoveryFeasibility;
  risk: Severity;
  recommended: boolean;
  actions: RecoveryActionDraft[];
  assumptions: string[];
  warnings: string[];
  requiresHumanApproval: true;
}
```

### Recovery rules

-   `strategyType` must be one of the six `RecoveryStrategyType` values
    listed above.
-   `estimatedCost` is a monetary amount; `currencyCode` identifies its
    ISO 4217 currency.
-   `recoveryTimeHours` is measured in hours.
-   `expectedImpactReductionPercent` is a percentage, not a fraction.
-   `feasibility` is `feasible`, `conditional`, or `infeasible`.
-   `risk` uses the shared `Severity` type.
-   `recommended` indicates whether the engine recommends the draft; it
    does not authorize execution.
-   `targetEntityId`, when present, must be a UUID string.
-   `estimatedLeadTimeDays` is measured in days.
-   `requiresHumanApproval` is always `true` in v0.4.
-   Recovery actions and plans are drafts. No action should be executed
    without an explicit human approval flow.

### Integration boundaries

-   `shared/types.ts` is the single source of truth for shared
    TypeScript interfaces and types.
-   `shared/INTEGRATION_CONTRACT.md` documents meaning, units,
    ownership, and integration rules.
-   `shared/sample-simulation-result.json` is the example payload and
    must conform to the shared types.
-   The frontend should consume shared types rather than independently
    redefining the same shared result structures.
-   Member 3 owns graph construction; Member 4 consumes the agreed graph
    snapshot.
-   Member 4 owns simulation calculations and recovery-plan generation.
-   Member 2 coordinates the contract and backend persistence; this does
    not transfer graph or simulation ownership to Member 2.

## 9. Validation and compatibility checklist

Before merging an integration change, verify:

-   [ ] TypeScript compiles with the shared types.
-   [ ] Sample JSON parses successfully.
-   [ ] All values assigned to UUID fields are valid UUID strings.
-   [ ] `GraphSnapshot` retains the agreed v0.3 shape.
-   [ ] Route metadata remains inside `GraphEdge.attributes`.
-   [ ] Scenario fields use `type`, `durationHours`, `targetKind`,
    `targetId`, and `startAt` as documented.
-   [ ] `SimulationResult` contains all required top-level fields.
-   [ ] `RecoveryPlanDraft.strategyType` uses the six-value
    `RecoveryStrategyType` union.
-   [ ] Currency fields use ISO 4217 codes.
-   [ ] Quantity units for inventory shortage and production loss are
    explicitly documented for the relevant data.
-   [ ] Unknown estimates are represented as `null`.
-   [ ] Recovery drafts require human approval and are not automatically
    executed.
-   [ ] Frontend, graph-service, and simulation-engine owners have
    reviewed the shared contract.
